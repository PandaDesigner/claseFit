## Why

The project ships with an `app.json` that declares `android.package = "com.pandadesigner.clasefit"`, an `assets/` directory with brand icons, and a JavaScript / TypeScript source tree that compiles cleanly via `npx expo export --platform android`. But there is no `android/` directory committed.

That gap hurts in two ways:

- **Reproducibility** — every contributor who runs `expo run:android` (or any CI runner that builds locally) triggers `expo prebuild`, which generates an `android/` folder from scratch. The generation is deterministic per `app.json` today, but future Expo SDK upgrades or prebuild plugin changes will drift.
- **Auditability** — the Android manifest, gradle build files, and resource overrides live in a directory that is not in source control. Reviewers cannot diff them in PRs; they only see the JS changes.

This change commits the `android/` directory generated by `expo prebuild`, with the standard Expo / React Native `.gitignore` patterns already in place (build outputs, gradle cache, local.properties). The only addition to `.gitignore` is `*.keystore` for the debug signing key (Android Studio's debug keystore is fine for development but should never leave the contributor's machine; production builds use a separate keystore managed via EAS / Gradle secrets).

No native source changes — the committed `android/` is exactly what `expo prebuild --platform android --clean` produces.

## What Changes

### New Capabilities

- `android-native-project`: the Expo-generated Android native project is committed for reproducibility.

### Modified Capabilities

- None.

## Impact

- **`.gitignore`**: adds `*.keystore` to the signing/keystore exclusion list. No other changes.
- **`android/`**: full native project (`build.gradle`, `settings.gradle`, `gradlew`, `app/build.gradle`, `app/src/main/...`, `app/src/debug/...`, etc.) is committed. Build outputs (`android/build`, `android/app/build`, `android/.gradle`, `android/local.properties`) stay ignored.
- **No production code change.** No test changes. No domain / application / infrastructure touches.

## Non-goals

- No native source modifications. The `android/` directory is exactly what `expo prebuild` produces.
- No `ios/` directory. iOS native is not yet committed (separate change when needed).
- No migration to Expo Modules migration assistant or any prebuild plugin changes.
- No keystore generation for production builds. Production signing continues via EAS / Gradle secrets (out of scope).
